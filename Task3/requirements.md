# Требования к безопасности

- Необходимо получить разрешение пользователя на хранение и передачу его биометрических данных и данных его гостей
- Все данные, которые будут передаваться, должны быть защищены с TLS 
- Строительная компания не хранит биометрические данные у себя, а только передает их зашифровано партнеру
- Партнерские системы осуществляют хранение, изоляцию с наименьшим доступом и верификацию данных
- Партнерские системы должны хранить полный лог с попытками доступа и результат верификации 
- Партнерские системы должны ограничить доступ к биометрическим данным только для ограниченного числа приложений в системе (RBAC)
- Биометрические данные должны приниматься через api, но не должны возвращаться через api
- Сервис по верификации входящих данных должен принимать входящую биометрию в зашифрованном виде по https, а возвращать только true / false
- Партнерские системы должны провести тестирование на Ddos и попытку внедрения вредоносного кода в запросы 


# Протоколы аутентификации и авторизации

- Для добавления/удаления биометрических данных используется уже существующее приложение строительной компании. Доступ в приложение имеют только авторизованные пользователи
- Доступ в приложение осуществляется по MFA по OAuth протоколу 
- Взаимодействие внутреннего приложения и внешнего партнерского происходит через REST API, используя JWT токены для авторизации. Токены выдаются централизованной системой и проверяются на каждой из сторон


# Организация взаимодействия 

- Партнерская система должна знать и хранить минимум необходимой информации, поэтому все биометрические данные разрешенных пользователей и автомобилей будут передаваться с уникальными UUID
- Приложение строительной компании и приложение партнера взаимодействуют по https протоколу с обязательным jwt ключом
